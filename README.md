# A股分析终端

本地 Web 版股票分析软件：QMT 日线导入 + 在线数据刷新、自选池、手动/自动选股、插件化交易策略、回测报告与 Excel 导出。

技术栈：Python 3.10+ / FastAPI / SQLite / pandas + React / TypeScript / Vite / ECharts。
数据源分两条互不干扰的路径：**日线 K 线只从本机 QMT 导出的两份日线文件（不复权 + 等比后复权）本地导入**，
库里存不复权价加每根一个等比累计复权因子；股票列表、基本面快照、季度财报、行业板块、大盘指数由东方财富（优先）/ 腾讯财经（自动降级）在线刷新，在线任务不写个股日线。

## 启动 / 停止

```bash
# 1. 后端依赖
pip install -r backend/requirements.txt

# 2. 前端（已构建过可跳过；改动源码后重新执行）
cd frontend && npm install && npm run build && cd ..

# 3. 启动（或直接双击 start.bat）
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8610
```

浏览器打开 http://127.0.0.1:8610

停止服务：双击 stop.bat（按端口 8610 结束服务进程及其子进程）。

建库路径：先在「数据中心 → 在线数据（公开接口）」跑一次「全量刷新」拿到股票列表与快照，再在 QMT 里把同一交易日的日线导两份（「不复权」和「等比后复权」），到「数据中心 → 本地数据（QMT 导入）」填两个目录并执行全量导入（实测 5573 只 / 1696 万行约 4 分半，含体检与成交额），详见下方「本地数据：QMT 日线导入」。

## 八大功能

| 模块 | 页面 | 说明 |
|---|---|---|
| 数据维护 | 数据中心 | 分「本地数据（QMT 导入）」和「在线数据（公开接口）」两块，都是必备数据、没有主次，只是来源不同：前者读本机 QMT 导出的**两份**日线（不复权 + 等比后复权）并合成「不复权价 + 复权因子」，分钟级建库且含成交额，是个股日线的**唯一**入口；后者在线刷新股票列表/基本面快照/季度财报/行业板块/大盘指数，不下载个股日线 |
| 股票自选池 | 股票自选池 | 可增删改名，池内股票可增删（跑过 `seed_sample.py` 时自带 核心持仓/观察池/打板池 三个池，空库则是 0 个，需自己新建）；列表带「收盘价日期」列，便于发现数据异常；点击股票进入个股详情页（K线/指标/财务） |
| 手动选股 | 手动选股 | 基本面（行业/市值/PE/PB/成交额/换手率/ROE/增速…）与技术面（MACD金叉、布林突破、多头排列、放量、箱体高度/现价位置…）条件自由组合，须同时满足；结果表同样带「收盘价日期」列（自动选股一致）；结果支持单选/多选/全选加入自选池 |
| 自动选股 | 自动选股 | 5 个条件框，权重之和必须为 100；框内条件按满足比例计分，加权总分排序取前 100 |
| 策略选股 | 策略选股 | 内置「低估值真成长 / 趋势放量 / 超跌企稳 / 长箱体震荡」四个选股器（条件写死在插件里，页面上只调门槛数值）；每天的名单按日期存进本地库留痕，可回看历史日期、勾选加入自选池；插件放在 `backend/app/selectors/`，新增文件即自动发现 |
| 交易策略 | 交易策略 | 内置 MACD+MA、双均线、海龟交易法、布林突破、KDJ 五个插件策略；插件放在 `backend/app/strategies/`，新增文件即自动发现；可勾选启用项 |
| 回测 | 回测 | 股票代码 + 区间（**二选一**：「最近 1/3/5/10 年」或「指定日期」；选了指定日期时开始日期必填、结束日期不填按今天，`结束<=开始` 或漏填都会写明原因并按不住「开始回测」）+ 资金（默认100万）+ 手续费（默认0.0003）+ 已启用策略下拉；点之前按钮旁就显示本次生效区间，结果里在个股K线上方再显示一遍「回测区间 …｜实际K线 N 根（首根 ~ 末根）｜成交价与金额按不复权真实价，曲线和买卖点按复权价」；汇总卡含「信号买不起一手」次数，非 0 时页面给出调大资金或换低价股的做法；生成个股K线（标注买卖点）、大盘指数、行业指数三条曲线，交易明细可导出 Excel |
| 全市场回测 | 全市场回测 | 不填股票代码，一次把区间内**所有**有日线的股票逐只跑同一个策略（每只独立一份初始资金，默认 100 万，K 线不足 30 根自动跳过）；约 1~2 分钟跑完，出「汇总分布 + 逐只排名表 + 按自然年分解」，结果整批落库可回看历史批次，点排名表某行下钻到该只的单只回测页；口径与坑见「全市场回测口径」 |

## 数据说明

- 个股日线只有 QMT 导入这一条路径，库里存的是**交易所口径的不复权价**（与行情软件逐分一致）加每根一个 `adj_factor`
  （QMT「等比后复权」推出的等比累计复权因子），后复权 = 不复权 × 因子，**正反可逆**；个股页可切「不复权 / 后复权」两个口径看同一份数据。
  **回测里两个口径都要用，各管一段**：信号（MACD/均线/布林等）用复权价，跨除权日才不会把分红送转当成暴跌；
  成交与现金用**不复权真实价**，因为「一手 = 100 股 × 真实股价」才是真实占用资金——拿复权价算手数会把高价股撑大 6~7 倍
  （600519 复权价近 5 年在 8963~17080 元，100 万连一手都买不起，于是所有买入信号被静默丢弃，2021~2024-09 一笔不成交）。
  除权除息日按因子比 `F_t/F_{t-1}` 折算持股数（等比因子分不开现金分红与送转，所以统一折算成持股数，**等价红利再投**），
  于是 `持股数 × 不复权价` 这条市值曲线在除权日不跳空、每轮毛收益严格等于该段复权区间收益（实测最大相对偏离 2.6e-15），
  代价是卖出笔的股数可能不是 100 的整数倍。资金不够一手而放弃的买入信号会计进 `summary.missed_buy_signals`，页面直接显示次数。
  在线源的 `fetch_kline` 只服务**指数K线**（`index_kline`），`kline_daily` 的唯一写入者是导入任务。
- `kline_daily.pct_chg` 是**全历史都有值的交易所口径涨跌幅**（1696 万行里只有每只股票的首根没有前收、共 5569 行为空）：非除权日取不复权收盘价环比；除权日先算
  「前收 × 旧因子 ÷ 新因子」并**按 0.01 元取整**得到除权参考价，再用收盘价对它求涨跌，与交易所公布值一致
  （末根还会用基本面快照再覆盖一次，要求快照交易日与该根同日，停牌股留空）。
  旧的仿射后复权（`复权价 = A × 不复权价 + B`）做不到这一点：环比会被 A、B 压缩，除权日能差几个百分点，
  所以那版口径下历史 `pct_chg` 只能整列置 NULL。仿射不可逆，本次迁移是整库重建而非原地转换。
  页面上显示的涨跌幅仍取 `fundamentals.pct_chg`（收盘口径），列表与个股页都不受该列影响。
- 复权因子是**分段常数**：QMT 四个价格偶发无法被同一因子整除到分（实测约 0.05% 的行，属它自身四价的舍入），
  导入时按「当日可行区间」续段。实测单只股票全历史约 12 次跳变（≈除权次数），相邻差 ≤0.05% 的多为噪声、
  因子最大回退 0.21%，故体检把「明显回退」的阈值定在 0.5%。
- 老股（如 920000 新三板转北交所）首根因子大于 1 是正常的，QMT 的因子基准早于导出窗口；
  只有首根**远小于 1** 才是选成了「前复权 / 等比前复权」（体检会拦）。
- 基本面快照的 `trade_date` 取**最近一个交易日**（读上证指数行情的时间戳），不是 `date.today()`：
  周末或长假里跑「日常刷新」若按今天写日期，末根（上一交易日）与同日这个条件就不成立，涨跌幅回填会整批跳过。
- 列表（股票自选池 / 手动·自动选股结果）的「收盘价日期」列取 `fundamentals.trade_date`，即页面上「最新价 / 涨跌幅」所属的交易日；
  与该股票 `kline_daily` 末根日期不一致时整格标红并在悬浮提示里给出末根日期，用于发现三类异常：缺基本面快照、新股或导入缺文件导致无日线、停牌导致技术面指标口径落后。
- 选股的「20日涨幅(%) / 60日涨幅(%)」与个股页指标都是**复权口径**（等比后复权，含分红），通常高于行情软件的不复权涨幅；
  从仿射口径迁到等比口径后这两个数值会略有变化。同组的「量比(当日/5日均量)」用成交量计算，与复权口径无关。
- 行业分类取数据源的行业板块（东财板块接口或腾讯板块排行，落 `boards` 表）。**行业K线不入库**（`board_kline` 表建了但从不写），
  回测里的行业曲线是每次按板块成分股日线等权合成的（`backtest.synthesize_board_bars`）。
- 一条已知降级来源：走腾讯供指数时，它的K线端点没有北证50（`bj899050`）的历史，`_refresh_indexes` 对失败的指数是
  静默跳过的，所以 `index_kline` 里只有上证/深证成指/创业板指/科创50 四条，**北交所个股回测的「大盘线」为空**（行业线仍正常）。
  （原先另一条「QMT 仿射后复权在高分红个股早年算出负价、55 只 / 8093 行指标无意义」随口径迁移消失：不复权价不可能为负，
  重建后已断言全库 `close > 0`。）
- 样本演示数据（15 只知名股票 + 3 个默认自选池，**不含日线K线**）可由 `python backend/scripts/seed_sample.py` 重建，只灌列表/快照/财报/指数；日线必须在「数据中心 → 本地数据（QMT 导入）」执行全量导入。
- 数据源限速：在线请求（股票列表、板块成分股、财报、指数K线）共用一个全局最小间隔串行放行，腾讯行情接口每请求最多返回 640 根K线，请求过快会被其 WAF 拒绝（HTTP 501），被拒时指数退避（60s 起、最长 900s）。可用环境变量 `STOCKCN_HTTP_INTERVAL` 调整间隔秒数（默认 1.0，实测该间隔可整夜跑完不退避；调到 0.4 以下会被封 IP，例如 `set STOCKCN_HTTP_INTERVAL=0.8` 后再运行 start.bat）。
  腾讯路径还把 DNS 抖动 / 连接重置 / 读超时这类**瞬时网络错误**视为可重试（最多 4 次、间隔 2/4/6 秒，`STOCKCN_HTTP_TRIES` 可调），
  免得一次抖动打断几十分钟的「全量刷新」；WAF 拒绝页仍是**不重试**直接进冷却（重试只会加重封禁）。个股日线改成 QMT 本地导入后，在线请求量比原先小了两个数量级。
- 基本面快照的 市净率 / 换手率 / 成交额 三项来自腾讯接口（板块成分股那一路的字段名是 `pn` / `hsl` / `turnover`，成交额单位为万元；
  ③ 补录股票走的批量行情 `qt.gtimg.cn` 是同一家另一套下标），都是当天收盘口径；「日常刷新」会刷新这三项。
- 股票列表走三级来源，覆盖 A 股全部上市公司（沪深主板 / 创业板 / 科创板 / 北交所，不含 B 股、新三板与存托凭证）：
  ① 东财 `push2` 全市场快照（字段最全，但部分网络下不可达）；② 腾讯板块成分股（**只有沪深A股**）；
  ③ 东财 `datacenter` 业绩报表花名册，只补录前两级漏掉的代码，并改用腾讯**批量行情**
  （`qt.gtimg.cn/q=`，板块排行接口答不出的科创板/北交所它都答）取这批股票的基本面快照。
  所以即使 ① 不可达、② 只给 4604 只，一次「日常刷新」后 `stocks` 仍会到 5579 只（4604 + 补录 975）；
  `list_date`（个股页的「上市日期」）不依赖这三条列表来源，是列表跑完后再单独一步从东财 `datacenter` 的
  **F10 公司概况**（`RPT_F10_ORG_BASICINFO` 的 `LISTING_DATE`，按 A 股类型过滤 8365 条 / 17 页，约 10 秒）回填的，
  实测覆盖 5572/5579 只（剩 7 只在接口里 `LISTING_DATE` 本身就是空的：001235、001381、301569、301660、301718、920162、920196，
  都是最新申报/刚上市的股票）；
  补录股票的行业取东财 `BOARD_NAME`、`board_code` 留空。
  新上市股票要等它首次披露某期财报才会出现在 ③ 里，因此「日常刷新」跑完仍缺新股时，隔几天再跑一次。
- 财报的 加权ROE（`fin_report.roe_weighted`）来自东财 `RPT_LICO_FN_CPD` 的 `WEIGHTAVG_ROE` 字段（半年报/年报为报告期累计值，不是年化）。
- 本地 QMT 导出的日线只提供 amount，日线里的换手率（`kline_daily.turnover`）由「流通市值 ÷ 现价」反推的流通股本估算，历史期内股本变动会带来偏差；选股用的换手率取上面快照口径的收盘值。
  「成交额(亿) / 换手率(%)」已挂进选股字段目录（结果表也有这两列）。
- `kline_daily` 只有 QMT 导入一个写入口，在线任务从不写它，所以不存在「两种复权口径混进同一只股票历史」的时序问题
  （原先的 `data_status.kline_source` 标记和它的互斥拦截已随在线K线下载一起删除）。
  日线库为空时「增量导入」会被拒绝，先做一次「全量导入」建库即可。

### 本地数据：QMT 日线导入

1. 在 QMT（迅投/券商端）里「导出数据 → 日线」**导两份**：一份选「不复权」，一份选「等比后复权」**（不要选「后复权」——它是 `A·不复权+B` 的仿射口径，不可逆；也不要选「前复权 / 等比前复权」——它们把基准锚在最后一根，早期因子会小于 1）**。两份都必须**在收盘后导**（15:00 之后，建议 18:00 以后）：
   盘中导出的最后一根是不完整的日内快照（价格与量额都偏低）；「增量导入」现在会重写最后一根，
   收盘结算后重新导出再点一次「增量导入」即可覆盖掉，不必重跑全量导入。
   按市场分别导出，得到
   `<导出目录>/SH|SZ|BJ/price_600000.txt`（或 `.csv`），表头为
   `timetag,open,high,low,close,volumn,amount`（`volumn` 是 QMT 的拼写，成交量单位为手）。
   库里存的是「不复权价 + 等比累计复权因子」，因子由这两份逐日反推，所以**两份必须是同一批次**（同一截止日期）。
2. 打开「数据中心 → 本地数据（QMT 导入）」，把**「不复权目录」和「等比后复权目录」都填到含 SH/SZ/BJ 的那一层**（QMT 常按复权口径再分一层目录，如 `E:\Project\QMT数据\不复权` 与 `E:\Project\QMT数据\等比后复权`；代码里不预置默认路径，但「检查目录」通过后页面会记住这次用的两个目录并在下次打开时回填），点「检查目录」：
   会报告两份导出的文件数、配对成功的股票数、各自的截止日期，缺文件的代码会**按市场统计并列出完整清单**（可一键复制，也可在文本框里全选手动复制），
   拿着清单回 QMT 补导出即可；还会抽检前 400 只（凑够 30 个可比样本即停）：
   若不足七成的末根收盘价与最新快照价相差 3% 以内，判为「疑似不是不复权」；若末根成交额对收盘快照成交额的中位比值低于 0.9，
   判为「盘中或未结算时导出」；另外逐日反推复权因子，识别除权次数、价格无法复现到分的行数、只出现在单边目录里的行数
   （这三项在 `/api/data/qmt/preview` 的 JSON 里是 `factor_events` / `factor_unreproduced` / `unmatched_rows`，
   页面对操作员只给一句「体检通过 / 体检发现问题」的结论，具体数字留在接口与这里），
   并对「首根因子远小于 1」（前复权特征）与「因子明显回退」（两份口径对不上）给出警告。
   `warning` 各条按「哪份导错了 + 回 QMT 该怎么选」写，供页面直接展示；改措辞时别动判定阈值。
3. 首次建库点「全量导入（首次建库）」（先写 `kline_stage` 暂存表，再一次性换名替换 `kline_daily`，中断不损坏已有数据；
   实测 5573 只 / 1696 万行约四分半）；日常点「增量导入（日常）」，会重写各股票最后一根K线并追加更晚的日期，
   所以当天导出错了重导一次即可覆盖修正。
4. 防误操作：导入前必跑一遍上面的检查。**「配对成功的股票不足 `stocks` 列表的 80%」是硬拒绝，勾「强制导入」也过不去**
   （多半是路径选错、两份不是同一批次，或 QMT 导出没跑完；空路径同样直接拒绝）。另外几种情况后端默认拒绝、勾「强制导入」可越过：
   抽检判定疑似不复权；抽检发现末根成交额明显低于收盘快照（中位不足九成，判定为盘中或当日数据未结算时导出）；
   复权因子无法逐日复现价格（两份口径不一致）；全量导入时导出的截止日期早于本地库（会把历史倒退回旧数据）。日线库为空时「增量导入」会被拒绝，先做一次全量导入。
5. 全量/增量导入后做两步回填：把每只股票最后一根K线的 amount、换手率回填到基本面快照（只填空值，不覆盖在线数据）；
   再把基本面快照的当日涨跌幅（交易所口径）写回最后一根K线的 `pct_chg`。历史K线的 `pct_chg` 在导入时就按复权因子逐日算好（除权日用除权参考价作分母），只有每只股票的首根没有前收、留空。
6. QMT 只供日线，列表/快照/财报/板块/指数仍只由「数据中心 → 在线数据（公开接口）」维护：点「日常刷新」即刷新股票列表/新股、基本面快照、近 2 期财报、指数与行业板块，
   日线库一行不动（首次建库点「全量刷新」，拉 12 期财报）。
   科创板与北交所也在这一步补进股票列表（见「数据说明」的三级来源），新股要先出现在列表里、
   它的 QMT 文件才会被「增量导入」匹配到（首次匹配到会把整个文件全历史入库，不用重跑「全量导入」）。

### 每日收盘后的固定顺序

1. 先「数据中心 → 在线数据（公开接口）」→「日常刷新」，拿到当日基本面快照（现价/涨跌幅/成交额）与新股列表。
2. 收盘结算后（建议 18:00 之后）在 QMT 把当日日线**按「不复权」「等比后复权」各导一份**，仍写到原来的那两个目录里。
3. 再「数据中心 → 本地数据（QMT 导入）」→「检查目录」→「增量导入（日常）」。

顺序颠倒不会损坏数据，只是末根涨跌幅回填要求「快照交易日与最后一根日线同日」，不满足时该列留空，第二天重跑即可补上。

想复核「在线任务确实不碰日线库」，可在服务运行时执行 `python backend/scripts/check_refresh.py`：它会触发一次「日常刷新」，并断言 `kline_daily` 的行数、末根日期、末根收盘价合计、末根复权因子合计前后完全一致，同时断言 `stocks.list_date`（上市日期）的覆盖数不降、且与在册股票数只差最新几只未披露的新股。

## 策略选股（插件式选股器）

与「手动/自动选股」共用同一份上下文：`screening.load_universe()` 返回每只股票的基本面快照 +
最近一期财报 + 最近 260 根**复权**日线算出的指标，所以手动选股能用的字段，选股器插件都能用。
差别在于：选股器把「必须同时满足的条件」写成代码，页面上只暴露门槛数值，并且每次运行都留痕。

内置四个（`builtin.py` 三个 + `box_range.py`，条件都是硬筛，score 只用于排序）：

| 选股器 | 硬条件 | score 构成 |
|---|---|---|
| 低估值真成长 `value_quality` | 0<PE(TTM)≤上限、0<PB≤上限、ROE≥下限、净利同比≥下限、流通市值≥下限 | 便宜程度 45 + ROE 30 + 增速 25（各按「达到门槛得一半、达到 2×门槛封顶」折算） |
| 趋势放量 `trend_volume` | 均线多头排列 + MACD 零轴上方 + 量比≥下限 + 20日涨幅落在区间 + 流通市值≥下限 | 量比 40 + 20日涨幅 30（两项都到下限的 4 倍才封顶）+ 收盘高于MA20 幅度 30（高于 10% 封顶） |
| 超跌企稳 `oversold_rebound` | 60日跌幅≥深度、RSI≤上限、收盘重新站上 MA20、流通市值≥下限 | 跌幅深度 40 + RSI 低位 30 + 站回 MA20 幅度 30 |
| 长箱体震荡 `box_range` | 见下文《长箱体震荡选股》一节 | 按现价在箱体内的位置分四档打分，档内不重叠 |

三个都会自动剔除：名称含 ST/退 的股票；没有日线或**最后一根日线日期与快照交易日不同日**的股票
（停牌、或本地导入缺文件）。所以「今天筛不出票」先去数据中心补当日日线。

留痕与配置：

- 表 `select_result`，主键 `(trade_date, selector_id, code)`。同一天重跑同一个选股器整批覆盖，
  **0 命中也会把当天该选股器的旧名单清空**（诚实反映「这次一只都没选出」）；换参数重跑同样覆盖，
  历史行里存的是当次参数。
- `trade_date` 取这批股票里最新的末根日线日期，不是系统当天 —— 休市日跑就落在最后一个交易日。
- 每行把命中当时的展示字段抄进 `attrs`（名称/行业/价格/市值/PE/PB/ROE/量比/20日涨幅…，
  `box_range` 还含箱底/箱顶/高度/位置/斜率/穿越次数/带内占比/脱离倍数/挖坑标记），
  隔天回看历史日期不会被今日行情改掉；`run_at` 是运行时刻。
- 启用项与参数存在 `kv_store` 的 `selector_config`；没有该键时视为全部启用。参数越界或非数字，
  接口直接返回 400，页面原样显示是哪一项、允许区间是多少。
- 接口：`GET /api/selectors`、`PUT /api/selectors/config`、`POST /api/selectors/run`
  （带 `selector_id` 跑一个，留空跑全部启用的）、`GET /api/selectors/results?selector_id=&date=`。

自己写一个选股器：在 `backend/app/selectors/` 新建 `my_pick.py`，重启服务后自动出现在页面上。

```python
from .base import Selector, num, signal, tradable

class MyPickSelector(Selector):
    id = "my_pick"
    name = "我的选股器"
    description = "一句话说明筛的是什么样的票"
    params_schema = [{"key": "mv_min", "label": "流通市值 下限(亿)",
                      "type": "number", "default": 50, "min": 0, "max": 5000}]

    def select(self, universe, params):        # universe 即 load_universe() 的结果
        out = []
        for code, ctx in universe.items():
            if not tradable(ctx):              # 剔除 ST/退、当日无新K线
                continue
            if not signal(ctx, "ma_bullish"):  # 技术面信号
                continue
            mv = num(ctx, "float_mv")          # 指标类字段也走 num(ctx, "close"/"rsi"/…)
            if mv is None or mv < params["mv_min"]:
                continue
            out.append({"code": code, "score": 50.0, "reason": f"流通市值 {mv:.0f}亿"})
        return out
```

想复刻视频/文章里的选股条件时，注意库里**没有**这些数据：龙虎榜、北向资金、概念题材（只有行业板块）、
股东户数、涨停/连板天数（可由 `pct_chg` 推但没有单独存列）、期货期权与港股。涉及这些的规则要么先补数据源，
要么换成近似条件（例如用「量比≥2 + 20日涨幅」代替「资金持续流入」）。

## 长箱体震荡选股（box-range）口径

来自视频号《老股民：不要预判下周板块轮动，真正可复用的是交易方法论》（需求文档
`.tmp-sph/video-strategy-box-screen.md`），只复刻其中**选股**那一环：找出「一波下跌出清之后横成一口箱子、
现价还在箱子里合适位置」的票。买卖点、仓位、条件单属于交易执行层，本模块不做。

**2026-10-05 重定结构**：旧口径只在 750 日窗口上算密集带，用户实盘对照后指出两条对不上的地方——
名单里看不出「一波下跌出清」（箱底集中在 2024-09 这类全市场β底，且旧条件的「现价÷3年最低≥1.3」几乎自动满足），
以及「箱体不明显」（旧口径只约束密集带，段内收盘极值振幅中位 250%，两成的时间在带外 1.5~3 倍，视觉上根本不是箱子）。
现在改成**先找底、再在底之后的段上算箱体**，价格一律只看收盘价。

计算用**等比后复权收盘价**（`close × adj_factor`），比值/百分比类字段与复权口径无关；箱顶箱底为了和页面的
「最新价」对齐，整段再除以该股最新复权因子换回今日价坐标（元）。

- **① 找底＝定出清点**：在最近 6 年（`DEFAULT_FIND_DAYS=1500` 个交易日）里取最低复权收盘，那天的日期就是
  `box_bottom_date`，即「下跌出清完成」那一点。并列最低取**最早**一根（实测取最早/最晚对段长分布几乎无差：
  段≥600 根的只数 2697 vs 2691）。
- **② 箱体段＝箱底之后（含当日）的日线**，段根数 `box_bars` 就是横盘时长，默认门槛 ≥750 根（满 3 年）。
  全市场实测 `box_bars` P50=640、P75=1075。
- **③ 箱顶/箱底＝段内密集带，不是段内极值**：把段内复权收盘按 ln 分成 0.25% 宽的格子
  （`BIN_SCALE=400`），取**覆盖 80% 交易日、且顶÷底比值最小**的那一段，格子左右边界就是箱底/箱顶。
  按比值而不是绝对价差量，因为箱体高度本身就是 顶÷底-1；同一批数据两种目标函数会选出完全不同的带
  （603696：比值口径高 105%，价差口径高 132%）。
- **④ 段内极值振幅 `box_ext_height`**（段内最高收盘 ÷ 最低收盘 - 1）承担用户规则「箱顶比箱底最多高一倍」，
  默认 ≤100%。全市场 P25=121%、P50=214%，所以这一条才是真正的形状门槛。
  带高与振幅的大小只受分箱边界约束：带不含段内极值时带高 < 振幅；带把两个极值都包进去（横得极齐）时
  带边各外扩一格，带高反而比振幅大到多 0.25%×(1+振幅)——实测 5570 只有 83 只属于后者，不是实现错误。
- **⑤ 出清回撤 `box_decline_pre`** = 1 − 箱底 ÷ **箱底之前那 750 个交易日**的最高复权收盘（窗口按全市场日历
  逐股倒推，不是「底之前的全部历史」，免得十几年前的老泡沬把回撤撑大）。全市场 P50=61.2%，默认门槛 ≥60%。
- **带内占比 `box_time_pct` 恒 ≥80%**（密集带定义决定的，实测最小 80.0）→ 只当展示列，**没有**进可选条件目录。
- **挖坑 `box_dip_60d`**：近 60 个交易日有**收盘**跌破密集带下沿、且现价又收回带内。改成收盘口径后有个新后果：
  段内最低收盘就是箱底（出清点），所以「坑」只能挖在密集带下沿与箱底之间——只有带高明显低于振幅的票才有这个空间。
- **年化斜率**对 ln(复权收盘) 关于**全市场交易日序号**在**箱体段**上做最小二乘，再 `exp(斜率×250)-1`：
  用全市场日历序号而不是「该股自身第几根 bar」，停牌缺口才会体现在时间轴上（实测两者对无停牌个股完全相同，中位差 0.0000%）。
  「上市年限」`box_years` 优先取 `stocks.list_date`（上市公告日，见上面「股票列表」一节），接口没给日期的退回首根日线；
  两者在 5570 只有日线的股票里对不上 39 只（33 只上市日更晚：29 个 920xxx 是新三板平移代码、600018 是重组后续号交易、
  000001/000002 撞上深交所 1990 年底的早期行情；另有 6 只首根更晚，最多差 33 天），所以它量的是「上市多久」而不是「有多少日线」，
  卡横盘时长用的是 `box_bars`（箱体段根数）。
- **命中条件**（`selectors/box_range.py`）：段根数 ≥ `seg_bars_min`(默认 750，375~1500) ／
  段内振幅 ≤ `ext_max`(默认 100，40~200) ／ 出清回撤 ≥ `decline_min`(默认 60，0~90) ／
  密集带高度 ≥ `height_min`(默认 15，0~60) ／ |年化斜率| ≤ `slope_abs_max`(默认 5) 且斜率 ≥ -3%（排除漫长的下跌中继）／
  收盘穿越中线 ≥4 次（固定）。`dip_bonus` 默认 10，只加分不硬筛。
  旧口径的「现价÷3年最低收盘 ≥1.3」和「箱体高度 ≤120%」两条撤掉：新结构下段内最低就是箱底，前者与位置%冗余；
  后者被 `ext_max` 支配（带高 ≤ 振幅 + 一格）。旧「上市满 4 年」也撤掉，横盘时长门槛本身就要求有历史。
- **分四档打分**：低买候选 位置 0~50%（60~100 分，越贴箱底越高）＞ 高卖提示 50~100%（30~59 分）＞
  破位观察 <0%（15~29 分，跌出箱体只等收回，**不算低买**）＞ 突破提示 >100%（0~14 分，追主升正是视频反对的做法）。
  挖坑按定义只会落在前两档，加分后封顶 100。
- **性能**：统计全在 SQLite 侧五遍扫描（段内最低收盘 → 最低那根的日期 → 段内 ln 分箱直方图 → 底之前 750 根最高收盘
  → 段内带 LAG 的聚合），全市场 5570 只一次算完 **59~73s**（机器空载实测），按 (基准日, 找底天数, 密集占比)
  缓存，命中不到 1ms，重启后端才重算。只有条件里真的用到 `box_*`（或跑 `box_range` 选股器）时才计算，普通选股不受影响
  （`screening.ensure_box` 懒加载）。库里不足 600+750 个交易日时出清段从最早一天起算，不足 `find_days` 天则整个口径不成立、返回空。
- **页面上的等待是两段之和**：`screening.load_universe()`（股票池 + 260 根K线的技术指标，空载实测 56s，缓存 5 分钟）
  ＋ 箱体计算（空载实测 59s），所以在【策略选股】点一次「立即运行」冷启动实测 95~182s（两次轮询之间完成），
  命中缓存再点只要 0.02s。全部查询共用一条 SQLite 连接（`db.py` 里的 `_lock` 串行），
  别的页面同时在筛选或回测时会排队 —— 实测并发下箱体计算从 60s 拖到 300~720s，那是排队不是口径变慢。
- **实测**（基准日 2026-09-30，默认门槛）：出池 **15 只**（无 ST）—— 低买 11 / 高卖 4 / 破位 0 / 突破 0，池内挖坑 5 只：
  华鼎股份、红旗连锁、双汇发展、立华股份、东诚药业、安科生物、华帝股份、奥特佳、凯龙股份、仲景食品、成都燃气、
  英特集团、龙佰集团、森马服饰、瑞丰银行。密集带宽 19~41%、段内振幅 47~97%、出清回撤 60~82%、横盘 3.8~5.6 年。
  放宽敏感性（其余条件不变）：`ext_max` 100→150 得 36 只、100→200 得 62 只；`decline_min` 60→40 得 40 只、→0 得 49 只。
  段≥750 根的票全市场 1754 只，说明挡人的是形状与出清两条，不是横盘时长。
- **白马老票为什么进不来**（2026-10-05 用新口径逐只核对，别再套旧口径的结论）：长江电力（振幅 100.3%、斜率 +11.6%/年、
  出清回撤只有 6.4%）、格力电器（105.0%／+13.5%／52.4%）、宝钢股份（153.5%／+5.3%／47.9%）、
  中国石化（181.8%／+15.0%／38.6%）—— 三条门槛一起挡，其中「跌得够深」这条根本过不了，因为它们 6 年内没跌出过 60%。
  伊利股份箱底落在 2024-09-18（那是全市场β底，不是一波下跌出清），横盘只有 494 根、带宽 10.5%；
  贵州茅台箱底 2026-06-26、段只有 68 根 —— 它还在跌，按口径就不该进。
  反过来**双汇发展**（箱底 2021-08-30、横 1233 根、振幅 55.4%、回撤 61.1%）在名单里：
  挡老白马的是「跌够深 + 横够久 + 箱子够扁」这三条，不是它们的市值或行业，`height_min` 调多少都没用。
- **复核**（2026-10-05 重做）：合成日线 10 只手算用例（标准箱体/单边下跌/底在窗口中间/收盘挖坑/盘中挖坑不算/
  复权因子≠1/新股不足窗口/中途停牌/基准日无K线/带外尖峰），箱底日期、段根数、密集带上下沿、出清回撤、穿越次数、
  带内占比、位置全部按手算核对；全市场 5570 只批量不变量（段根数范围、箱底日期必在窗口内、带高与振幅的格宽关系、
  带内占比 ≥80%、回撤 ∈(0,100)、挖坑必收回带内、脱离倍数 ≥1）全过；再与一份**独立参考实现**
  （纯 Python 逐只重算，不复用它的 SQL/滑窗）在抽样上逐字段一致。

## 全市场回测口径

「回测」页一次只跑一只，看不出策略在整片市场上到底行不行：一只赚 200% 可能只是运气，
需要知道「随机抓一只有多大概率赚钱、典型结果是多少、分布长什么样」。全市场回测就是把这个
判断做一次，主体是**成绩单**（逐只排名），组合曲线只是参考。

- **资金口径：每只独立一份初始资金**（默认 100 万，逐只从头算），不做全市场共享一个资金池。
  共享池会让前一只的盈亏改变后一只买得起几手，跨只不可比，也回答不了「这策略换任何一只会怎样」。
  K 线不足 30 根的直接跳过（策略没足够历史算指标），跳过的只数在批次里写明。
- **两条等权净值曲线**：把每只的净值（区间市值/初始资金）按日**等权平均**，起点 1.0。
  左图是全部参与股票的等权净值，只说明「平均形状」，真正的分布要看下面的直方图和分位数；
  右图是按这批结果**事后**挑出的超额收益前 20/50/100 只重放的等权净值，页面标红警示：
  实盘不可能提前知道是谁，这条线必然是这批里最好看的，**只能当上限参考**（幸存者偏差）。
  实测这组参数下全体等权 1.0 → 1.34，事后挑前 20 只 → 8.76，差 6 倍多，这就是别拿右图当预期的理由。
- **分布**：分位数 P5/P10/P25/P50/P75/P90/P95（把 N 只从最差排到最好，P10 就是第 10% 名的数，
  只有 10% 的股票比它更差），配一张固定档宽的直方图（-100/-50/-30/-20/-10/0/10/20/30/50/100/200/300/500，
  两端越界各单独成档，各档只数之和 = 参与只数（实测超额口径有 473 只低于 -100%，
  少了这一档直方图就对不上总数）。为什么要看分布：均值被少数大赚的股票拉高
  （实测这组参数：收益中位数 +1.28%，均值却有 +33.85%，因为最好一只是 +2001.82%），
  双峰/长尾光看均值和中位数是看不出来的。
  可切「策略区间收益」和「超额收益（策略 − 买入持有）」两个口径，后者才回答「有没有跑赢拿住不动」——
  这批的超额中位数是 -0.99%，也就是说**一半股票用这个策略还不如买入放着不动**，
  这种结论只看总收益排名是看不到的。
- **按自然年分解**：每只按当年年末净值 / 上一年年末净值 - 1 计当年收益，当年K线不足 2 根的不计入该年
  （长停牌、那年才上市、年内已退市），第一年没有「上一年末」可参照，基准取初始资金；
  所以每年的覆盖只数会逐年后增
  （实测 2021~2026 依次为 4489/4912/5230/5331/5445/5545 只），最后一年是截至结束日期的半年。
  同一段策略的年度胜率差得很远（实测 52.8/29.1/38.8/56.3/59.5/35.3%），说明某年难赚多半是市场问题，
  不是代码算错，也别只用一年下结论。
- **与单只回测同一份记账核心**：信号在复权价上判定，成交与现金走不复权真实价，除权除息日按
  `F_t/F_{t-1}` 折算持股数（等价红利按除权日价再投）。单只页和跑批共用 `backtest.walk_ledger`，
  所以批量成绩单与单只回测**逐值一致**（验证时随机 9 只 + 最好/最差/最深回撤共 12 只对账，
  收益率、买入次数、委托笔数、买不起一手次数四项全等）。
- **运行约束**：跑批约 1~2 分钟（实测 dual_ma 全市场 91~94s：取数 36~37s + 信号与记账 39~41s；早先逐根
  iterrows 的写法全市场要 2 小时以上，改成只在「信号日 + 复权因子变化日」推进状态机才快，且与逐根版等价）。
  启动接口把批次号和 running 状态一起直接返回，不再回读一次 kv——读 kv 要排在跑批线程的全市场查询后面，
  按钮点下去会十几秒不出进度条。
  全进程共用一条 SQLite 连接和一把可重入锁，**跑批期间其它页面会排队转圈**，页面因此写明
  「等它跑完再操作」；与「数据中心」的数据更新互斥（两者都要扫全市场），更新进行中启动跑批会被直接挡下。
- **留痕**：每批一行写进 `bt_batch`（区间、每只资金、费率、策略与参数、参与/跳过只数、耗时、
  汇总 JSON），逐只成绩单一行写进 `bt_batch_item`，批次号为 `策略_起_止_时间戳`；
  跟策略选股的历史名单一样可回看，页面「历史批次」下拉直接打开，排名表支持排序、代码/名称搜索、
  每页 50 条分页。
- **点行下钻**：排名表点一行，把这一行的代码连同**这一轮记录的**策略、参数、区间、每只资金、费率
  一起传给「回测」页（取 `bt_batch` 里的值，不是页面表单当前填的值，所以回看历史批次也不会串味），
  区间自动切成「指定日期」，等策略列表加载完就自动跑一次。带不过来的两种情况不静默兜底：
  该批策略已被停用时不自动跑，红字写清「自己选策略、把区间改成 X ~ Y 再点开始回测」；
  区间在这页不成立时同样只填不跑，提示改日期。参数按策略 schema 补齐后再覆盖，
  避免留痕里缺键时把 `undefined` 发给后端。
  验证：两个历史批次各抽 3 只（首行/中位行/末行），把记录口径原样 POST 给单只接口，
  收益率、委托/买入笔数、手续费、区间与参数回显 23 项断言全等（下钻就是这一行的数字）。
- **页面状态保持**：SPA 没有 URL 路由，切页面就是卸载 / 重挂载，所以这一页把离开时的状态
  （区间模式与日期、每只资金、费率、策略与参数、已打开的批次、排序列与方向、页码、搜索词、
  分布口径、曲线前 N）记在模块变量里，回来原样接上，并按原口径后台重取一次结果与曲线
  （先显示上次的数据，拉到就换）。只活过一次卸载，刷新页面（F5）回到默认值。
  若记住的策略这期间被停用，退回启用列表第一个并把参数换成它的默认值——下拉框显示的就是
  即将生效的策略，不静默留旧参数。
  验证（浏览器实测）：点开 dual_ma 历史批次 → 表头按手续费降序 → 翻页到 51~100 →
  搜「银行」（37 条）→ 分布切超额、曲线切前 50 → 切到【回测】【策略选股】再切回，
  15 项状态逐值一致；点行下钻 603917 自动跑出 155.13%、委托 80 笔（与那一行一致）后

  停用分支也实测过（同一页，另开一次）：把 dual_ma 在【交易策略】页取消勾选后回到本页，
